# Hover Zoom AI Context

> update: 2026-01-08 | status: Strict Hotkey + B 站 Fix

## 架构

遵循 **单一真理 (Single Resolver Type)** 原则，分离数据、逻辑与 UI。

```text
hover-zoom/
├── components/ui/       # 设置面板
├── logic/engine.ts      # DNR/Anti-hotlink
├── content/             # Content Script
│   ├── resolvers/       # URL 解析
│   │   ├── rule-resolver.ts   # 站点规则 + needsAsyncResolve
│   │   └── image-resolver.ts  # 通用图片提取
│   ├── utils/           # 工具 (proxy-utils, hotkeys, resource-key-helper)
│   ├── viewer/          # 浮层展示
│   └── styles/          # 样式
├── rules/               # 规则库 (基于 Hz+/Imagus/PhotoShow)
│   ├── core.ts          # Resolver/RuleConfig/RuleEngine
│   └── definitions/     # 站点规则 (bilibili, twitter, reddit...)
└── types.ts             # 共享类型

# Content Entry (src/content/)
hover-zoom.ts            # 主入口 (精简)
hover-zoom-state.ts      # 状态管理
hover-zoom-events.ts     # 鼠标事件
hover-zoom-keys.ts       # 键盘事件 (strict keyup handling)
hover-zoom-actions.ts    # 触发逻辑 (needsAsyncResolve → startTimer)
```

## 数据流

```
mouseover/keydown → hover-zoom-events/keys → tryTrigger
    ↓
isValidTrigger → detectQuick || needsAsyncResolve → startTimer
    ↓
resolveEnhanced → RuleEngine/ImageResolver → EnhancedResult
    ↓
viewer.show()

keyup/mouseout → cancel() → viewer.hide()
```

## 规则系统

核心思想：**RuleConfig as Syntax Sugar**. 运行时只有一种类型：函数。
**Resolver**: `(ctx) => Promise<string | Result | null>`
**Sugars**: `replace` | `selector` | `api`
**ASYNC_RESOLVE_PATTERNS**: B站视频链接等需要 API 解析的元素模式

## 布局算法

1. 评估四向空间
2. 原图能放入 → 选最佳方向
3. 否则 → 选最大空间并缩放
