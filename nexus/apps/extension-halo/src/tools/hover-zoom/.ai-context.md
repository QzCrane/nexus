## 架构

遵循 **单一真理 (Single Resolver Type)** 原则，分离数据、逻辑与 UI。

```text
hover-zoom/
├── components/ui/       # 设置面板
├── logic/engine.ts      # DNR/Anti-hotlink
├── content/             # Content Script
│   ├── resolvers/       # URL 解析
│   ├── utils/           # 工具 (proxy-utils, hotkeys, resource-key-helper)
│   ├── viewer/          # 浮层展示 (含 pin-controller.ts 拖动/缩放)
│   └── styles/          # 样式 (含固定模式 UI)
├── rules/               # 规则库 (基于 Hz+/Imagus/PhotoShow)
│   ├── core.ts          # Re-exports (types + compiler + engine)
│   ├── types.ts         # 核心类型 (SiteRule, RuleConfig...)
│   ├── compiler.ts      # RuleConfig → Resolver 编译器
│   ├── rule-engine.ts   # RuleEngine 类
│   ├── utils/           # 通用工具 (parse.ts: parseEmbeddedJson, sortByBandwidth)
│   └── definitions/     # 站点规则 (一域名一文件)
└── types.ts             # 共享类型

# Content Entry (src/content/)
hover-zoom.ts            # 主入口 (精简)
hover-zoom-state.ts      # 状态管理
hover-zoom-events.ts     # 鼠标事件
hover-zoom-keys.ts       # 键盘事件 (strict keyup handling)
hover-zoom-actions.ts    # 触发逻辑 (needsAsyncResolve → startTimer)
```

## 数据流

```text
mouseover/keydown → hover-zoom-events/keys → tryTrigger
    ↓
isValidTrigger → detectQuick || needsAsyncResolve → startTimer
    ↓
resolveEnhanced → RuleEngine/ImageResolver → EnhancedResult
    ↓
viewer.show()

keyup/mouseout → cancel() → viewer.hide()
```

## 规则系统

**架构原则**:

- **规则自包含** - 所有规则逻辑（含 triggers）只在 `rules/definitions/`
- **一域名一文件** - `bilibili.ts`, `twitter.ts`, `reddit.ts`...
- **公共提取** - 工具函数在 `rules/utils/`（非 definitions）
- **不污染其他模块** - `rule-resolver.ts` 从 engine 动态获取 triggers

**核心接口**:

```typescript
interface SiteRule {
  id: string; // 唯一标识
  hosts: string[]; // 匹配域名
  match?: RegExp; // URL 匹配
  triggers?: string[]; // 异步触发选择器 (API 解析场景)
  resolve: RuleConfig; // 解析逻辑
}
```

**RuleConfig**: `Resolver` | `{ replace }` | `{ selector }` | `{ api }`

## 布局算法

1. 评估四向空间
2. 原图能放入 → 选最佳方向
3. 否则 → 选最大空间并缩放
