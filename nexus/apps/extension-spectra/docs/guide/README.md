# SPECTRA 入门导读（从零开始）

这个目录回答的是：**"我不懂前端，也不懂浏览器扩展，怎么才能看懂 SPECTRA 里到底发生了什么。"**

它和 `docs/control/`、`docs/architecture/` 的关系必须说清楚：

| 目录 | 是什么 | 有没有规则效力 |
| --- | --- | --- |
| `docs/guide/`（本目录） | 教材。解释名词、讲清机制、把代码位置指出来 | **没有**。这里写的一切都是解释 |
| `docs/control/` | 规范。每个主题的唯一 owner | **有**。行为以它为准 |
| `docs/architecture/` | 运行时拓扑与准入的唯一 owner | **有** |
| `docs/reference/protocols.md` | 跨上下文协议的唯一 owner | **有** |
| 源代码 / 契约 / 测试 | 最终事实 | **最高** |

**为什么分成两层**：规则如果写两遍，两份迟早会不一致，然后没人知道该信哪份。所以这个仓库的做法是——规则只写在 owner 里，教材只负责"让人能读懂 owner"，教材里不复制任何数值和判定条件。

如果你在教材里看到某个数字（比如"64 毫秒"），那是为了讲清原理而举的例子，**权当参考**；真值永远去 owner 文档或常量定义里查。

## 一句话版本

如果你想在三十秒内拿到全局：

> 网页是一棵可以随时被改写的树；浏览器只允许你在特定的时刻（任务、微任务、帧）才看得见它的真相；扩展是挂在浏览器上的一组独立程序，它们各自待在不同的房间里，只能靠传纸条说话；而 SPECTRA 要做的，是在这样一棵随时变化的树上，**始终知道自己在控制哪一个东西**。

## 术语对照的入口

不懂的词直接查 [glossary.md](glossary.md)。那里按"你可能听到的说法 → 它实际指什么 → 在本项目里对应哪个标识"来组织，不是词典。

## 维护规则

- 本目录只做解释，不改行为。任何"应该怎样"的结论必须落在 `docs/control/` 或 `docs/architecture/` 的 owner 里。
- 教材可以引用行号，但行号会随代码变化；引用时以函数名为主、行号为辅。
- 新增教材页时，同步更新本文件的阅读顺序表。
