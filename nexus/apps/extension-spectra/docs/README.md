# SPECTRA documentation

SPECTRA documentation is organized by authority so control semantics, runtime topology, wire protocols, security, source admission, planning, public copy, and historical evidence cannot compete.

```text
docs/
├── README.md
├── control/
│   ├── README.md
│   └── 01..08 topic owners
├── architecture/
│   ├── runtime.md
│   └── media-source-admission.md
├── reference/
│   └── protocols.md
├── security/
│   └── remote-control.md
├── roadmap.md
├── _archive/2026-Q3/
├── control-architecture.md       # generated byte-identical compatibility mirror
├── architecture.md              # deprecated migration redirect
├── protocols.md                 # deprecated migration redirect
├── remote-security.md           # deprecated migration redirect
└── cors-data-flow.md             # deprecated migration redirect
```

## Normative owners

- [Control architecture](control/README.md): product semantics, per-capability strategy, state, media/video behavior, algorithms, implementation ownership, invariants, and release gates.
- [Runtime architecture](architecture/runtime.md): context topology, loading, storage, leases, and runtime ownership.
- [Media-source admission](architecture/media-source-admission.md): irreversible Media WebAudio eligibility and coverage proof.
- [Runtime protocols](reference/protocols.md): cross-context envelopes, validation, state flow, READY, and leases.
- [Remote-control security](security/remote-control.md): pairing, authentication, session binding, expiry, and network disclosure.

## Non-normative layers

- [Roadmap](roadmap.md): sequencing and unresolved work.
- [Historical evidence](_archive/2026-Q3/README.md): dated implementation, regression, and release snapshots.
- [Product README](../README.md), [privacy policy](../PRIVACY.md), and [store copy](../store-listings/README.md): public projections that must remain narrower than verified behavior.

## Compatibility paths

`control-architecture.md` remains because existing executable tests and static verification read that historical path as the complete 51-capability matrix. It is a generated byte-identical mirror of [`control/04a-algorithm-matrix.md`](control/04a-algorithm-matrix.md), has no independent edit authority, and is checked for exact equality by `docs:check`.

The remaining former paths are short deprecated redirects with removal dates. They contain no normative behavior.

`bun run docs:check` runs the documentation checker in strict mode. It fails on and after a redirect's UTC `remove_after` date; a migration path must then be removed or receive a newly reviewed, explicitly bounded migration decision. This prevents compatibility templates from becoming permanent duplicate structure.

## Authority rule

Executable contracts, source, tests, Chrome integration, production artifacts, and release gates remain implementation truth. A document is a runtime authority only for the scope explicitly assigned above. Compatibility mirrors and redirects cannot define or amend behavior.

## Release-gated totals

The control owner mirrors these executable totals:

- 51 contract capabilities;
- 28 persistent snapshot fields and 23 momentary operations;
- 50 audited source algorithms (`ALG-001..ALG-050`);
- 44 static invariants (`SCTRL-001..SCTRL-044`).

A total changes only with the corresponding contract, implementation catalog, tests, owner documentation, and verifier.
