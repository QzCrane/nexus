# 控制语义决策：身份、证明与预测的边界

这份决策记录回答"为什么不能那样做"。这些问题在实现里被反复重新讨论，因为答案原先只
存在于会话记录和 06 的事故叙述里。规则本身仍在 [control](../../apps/extension-spectra/docs/control/README.md)，
本文只记录取舍与被否决的方案。

## D1. 一个媒体对象有四种身份，不能压成一种

**状态：部分实施。** L1/L4 已按此实现；L2/L3 的拆分尚未落地（见
[故障索引](../../apps/extension-spectra/docs/control/09-failure-index.md) 前两条，状态 `open`）。

- **L1 会话**：`tabId + documentId + generation`。换页即整份作废。
- **L2 控制**：`frameId + mediaId`。换人：取消在途、清恢复义务、重放 desired。
- **L3 资源**：`sourceRevision`。同一元素换第 N 段流：**重基 + 重校验**，不是失败。
- **L4 证据**：`owner + epoch + selection + revision`。只排序，不作判决。

**决定**：`sourceRevision` 不参与"还是不是同一个控制对象"的判定；`mediaId` 变化才算换人。

**理由**：直播页每次重建 `MediaSource`（开播、广告转正、码率切换、卡顿恢复）都会改变
`src`/`srcObject`/`load()`，但元素没有换、用户的目标没有换。把资源变化当成控制变化，
会让在途写入在下一个 `await` 点被判过期，并清掉尚未完成的恢复义务。

**被否决**：给 `targetKey` 保留 revision，但"重试到成功"。否决原因：播放器启动期可以连续
换源，任何常数都会被超过；而且它把身份保护换成了运气。

**反方条件**：如果某个站点在换流后复用同一个元素但语义上变成另一个播放器（真的换了内容），
那么"重基"会把旧目标的值写进新内容。这需要 `isConnected` 之外的证据；目前的判定是
"同一元素 = 同一控制对象"，例外站点必须写进 `site-adapter-registry` 的 declared 行，而不是
放宽全局规则。

## D2. `speed` 不能拆分写入与证明

**决定**：`speed`、`playing`、page-controller 写入与处理器输出，始终在同一事务内等待稳定证明。
只有合格的标准 DOM 音量/静音可以先答 `written`。

**理由**：倍速的物理写入与"真的变了"之间隔着一个站点控制器。先答 `written` 会把一次没生效
的暂停或调速报告为成功，再靠后续观察翻回——那正是"按了暂停还在放"的观感来源。

**被否决**：对所有字段统一用乐观 ACK。否决原因：分离的收益（更快的 UI）在离散设置上
远小于代价（把失败报成成功）。

## D3. 超过 100% 不允许预测站点 UI

**决定**：`boost > 100` 走 Capture 处理器增益或 Web Audio；站点的音量条不在同步范围内。
只有 ≤100 且存在 declared 适配时，才谈得上"站点 UI 同步"。

**理由**：站点没有"120%"这个概念。任何试图用合成指针事件驱动站点滑块的方案，都会在
站点自己的状态回写时被覆盖，并且把"扩展的值"和"站点的值"变成两个互相打架的事实。

**被否决**：用 `dispatchEvent` 造 `input` 事件驱动站点滑块。否决原因：伪造用户输入，
且站点可以合法忽略它。

## D4. 页面内快捷键拿不到 Capture 准入

**决定**：页面内按键不产生 Capture 准入；只有 Popup 与 `chrome.commands` 的手势可以。
页面控制器声称播放速率超过 100、活跃 processor 存在、或 `mediaWebAudio === true` 时，
才允许 `boost > 100`；否则 boost 落回 1，有效音量停在 100，且所有表面用同一上限显示。

**理由**：Chrome 只把用户激活授予扩展自己的 UI 与命令。页面内按键的"手势"属于页面，
不属于扩展。把两者混同，会得到一个有时能开处理器、有时不能的系统。

**被否决**：在页面按键时复用最近一次 Popup 手势的准入。否决原因：准入是一次性的，
复用等于把它变成长期许可证。

## D5. 不用选择器定位元素

**决定**：每个 `HTMLMediaElement` 在注册时获得一个 `mediaId`；所有控制、ACK、观察都带
`{documentId, frameId, mediaId, sourceRevision}`。

**理由**：选择器描述"文档里符合某个形状的节点"，而控制需要的是"我刚才测量的那个对象"。
站点会在运行时替换节点、把同一个选择器指向另一个播放器、或在 shadow DOM 里再放一个。
`mediaId` 是唯一能跨 await 保持不变的身份。

**被否决**：用 `querySelector` + 属性指纹在每次操作时重新定位。否决原因：指纹会漂移，
而且"重新定位到另一个元素"与"目标已经离场"在语义上必须区分。

## D6. 事实可以触发意图，意图不能伪造事实

**决定**：页面观察（observation）只用于排序与投影；恢复（restore）是意图，必须走与用户
手势相同的写入路径与栅栏。`phase=error` 与 `writeState=unconfirmed` 不可互换。

**理由**：把"不知道"报成"失败"会让用户重试一个已经成功的操作；把观察当命令会让页面
的一次临时状态变成持久偏好（例如把自动播放策略导致的静音回放进下一次访问）。

**被否决**：观察到的值直接写回 desired。否决原因：见上；这也是 `SCTRL-055` 存在的原因。
