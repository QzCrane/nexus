## 原决策失误与反方检验

原有规则和 add-dependency 技能要求在添加依赖时核实必要性、版本、许可和性能，却没有把“准备手写通用能力”作为同等触发条件。因此不加依赖反而容易跳过平台、现有依赖和成熟实现的比较。将“修正当前实现”默认等同于“继续维护当前算法”，以及以少依赖或已有投入作为保留理由，是应修正的决策顺序。

不能据此反向得出“所有自研都是浪费”。扩展的目标身份、发送者权限、捕获票据、会话代际、唯一资源所有者、实际完成顺序、旧操作退休、用户数据迁移和最终产物验证，不能由CSV解析器、UI框架、IndexedDB包装器或一般队列自动提供。库本身也可能不匹配运行宿主、语法、许可证或资源预算；这些是要验证的反方条件，而不是事前不做选型的理由。

这次没有完整工时、历史决策和反事实接入记录，不能计算“之前浪费了百分之多少”或以提交数、代码行数、候选包数代替成本。可直接归因的是在全面优化阶段遗漏了前置复用比较；不能未经逐项追溯，把继承自旧分支的每行代码都说成本轮新写。

## 既有工作的处置

| 工作类别 | 当前判断 | 后续处置 |
| --- | --- | --- |
| 文档/目标身份、权限、捕获、代际、确认、唯一写入和退出清理 | 必需的领域工作，选库不会使其失效 | 保留现有合同、实现和负例；第三方只能通过这些边界接入 |
| 数据错误反例、标准向量、字段保真、事务abort、并发顺序与真实浏览器回归 | 持续有价值的验收资产 | 测试正确行为而非旧实现细节，用于替代引擎的准入和升级 |
| 手写CSV/YAML/Markdown/HTML实体/SQL及代码排版压缩/X.509/Diff等通用引擎 | 长期自维护必要性没有被充分证明，有明确可避免的实现与维护成本 | 停止无边界补功能；先验证成熟引擎，迁移后删除旧引擎，不保留双重权威 |
| 最近UUID/TOTP/Protobuf/JWT等确定性修复 | 修正行为有价值；算法代码可能再替换，存在部分返工 | 保留已修语义与全部正确向量；不把做过修复当作永久保留算法的理由 |
| Windows路径、Docker身份、真实读取、事务完成等已定位错误修复 | 具体错误要修，不能以将来换库为由保留错误 | 保留正确修复；通用文件/API胶水能复用时再收敛，不倒退平台检查 |
| 反复冻结旧候选、重复传输、help-only命令、失效补丁重放和过期PR状态 | 可避免的交付流程成本，失败不能包装成有效开发成果 | 复用一套执行入口；按精确基线补丁/树校验，不重放旧改动覆盖更新；只在真实冻结时做完整发布收口 |

紧急修复例外仅适用于当前风险需要先阻断且替代引擎尚未完成兼容验证的情况。必须说明具体障碍、保留复现和临时实现的退出条件；不能把所有标准算法修补事后都解释成“必需的应急工作”。发现新问题有价值，也不能抵消本可避免的实现和流程返工。

## 选择与接入顺序

先定义所需语义、实际运行世界和失败反例，再比较原生能力、已有依赖、维护中的专用库及自研。通用机制优先由成熟实现承担；自研保留的是确实缺失、不可绕过的领域约束。简单数值/URL/单位操作不因本决策被强制加大框架。

第一批处理数据和输出语义错误：CSV、YAML、JSON保真、SQL、代码压缩、Markdown与最终HTML清洗、实体、证书、Diff。保留现有jose和pdf-lib并修适配，不以换库代替目标授权、全部PDF输出和生命周期修复。

共享层按实际需要引入单一IndexedDB封装和结构schema；测试优先补属性生成、实际Preact挂载、事务行为和自动无障碍检查。接入一个真实入口并通过现有负例后才扩展到同类入口，不先建无需求的插件平台。

代码编辑器、虚拟列表、全文索引、图像重采样、复杂ZIP、WXT等属于带明确条件的机会。只在现有业务和测量证明需要时推进；不得把所有候选同时安装。R55当前明确不进行整仓WXT迁移，R56只参考独立实现和依赖选择，不整体嵌入工具应用。

每项迁移必须说明：哪个包和入口接管哪部分代码；Nexus保留什么政策；旧算法在何条件下删除；既有数据怎样保持或迁移；替代失败时怎样恢复。成熟库实现已选，不意味着需要再写一层同等复杂度的自有parser包裹它。

## 具体准入和退出标准

具体包先验证官方发布物、许可证和NOTICE、直接与传递依赖公告、运行宿主和构建方式，再固定锁文件中的确切版本。动态代码生成、Blob worker、DOM需求、单renderer、静态扩展资源、native tsc CLI与compiler API分域都按真正保留的产物检查。

按原输入和公共向量验证正确性；按所有相关调用者验证相同合同；涉及Chrome身份、权限、导航、worker和真实持久化的行为仍做实际浏览器检查。自动扫描和随机测试不能替代领域判定，不保留错误的实现特定断言来强迫新引擎复制缺陷。

测量实际首次入口、懒加载块、worker启动、内存和任务耗时；同业务、同浏览器、同工作负载比较，不拿npm包体替代生产成本，不通过删除功能换指标。需要限制时先依据算法、数据范围与实际资源测量，不虚构统一百分比或时间阈值。

先保留原数据再迁移，迁移确认后切换唯一写入者；旧ID不重生成，已舍入数字或遗失的算法参数无原始资料时不能声称可以自动恢复。替代通过后删除被接管的旧引擎、重复规则和无用依赖；失败时退回候选比较，不放宽安全约束。

本次仅将决策接入规则与技能入口，并通过文档/结构完整性校验。它不是已经实现了能自动识别所有新手写算法的语义门禁；审查仍须针对实际diff进行。不要用另一个庞大自研扫描器来补偿本次缺失的复用判断。
