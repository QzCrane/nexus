# Feature Finish Workflow

这是一个强制执行的工作流。当用户要求“完成任务”、“提交代码”或当你认为代码逻辑已经实现完毕时，**必须严格按顺序执行以下所有步骤**，严禁跳过。

## 步骤 1：文档一致性审计 (Doc Sync)

**目标**：确保你刚才修改的代码没有破坏现有的 Markdown 架构。
**动作**：

1. 回顾你在本次对话中修改过的所有业务文件（特别是 `.ts`, `manifest.json` 等）。
2. 在工作区中搜索关联的 `.md` 架构文档（如 `docs/architecture.md`, `plan.md` 等）。
3. **你必须主动判断**：刚才的改动是否新增了数据流？是否废弃了某个接口？是否改变了生命周期？
4. 如果有，**必须立即编辑相关的 `.md` 文档并保存**，保持文档内容完美互补，并加上时间戳标记。

## 步骤 2：代码规范与类型检查 (Type & Rule Review)

**目标**：物理防止低级错误和红线违规。
**动作**：

1. 检查修改的代码是否包含 `any`、未捕获的 `Promise` 或静态硬编码的 URL。如果有，立即修复。
2. （Turbo）运行全局类型检查：
// turbo
`npm run check-types` 或者使用你的 lint 工具。如果有报错，必须先修复报错。

## 步骤 3：提交规范预演 (Git Commit)

**目标**：生成符合 Conventional Commits 规范的 Git 报告。
**动作**：
当你通过了步骤 1（文档更新）和 2（不带红线错误），向用户输出总结语：
> "✅ 规范检查完毕。文档同步已完成。以下是为您准备的提交信息草案："
>
> `feat/fix/docs(module-name): 具体的英文描述`

**警告：除非你在第一步确认了不涉及文档更新，或者完成了文档修改，否则绝对不许向用户报告任务结束！**
